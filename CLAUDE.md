# Notes for coding agents

ClaudeDesk is a Windows tray inbox for Claude Code sessions. `desk.py` (stdlib-only CLI) appends messages to JSONL files; the tray app shows them in a local web UI (Edge WebView2 via pywebview) and writes the replies. See `CONTRIBUTING.md` for the full contributor guide.

## Where things live

- `desk.py`: the CLI sessions call (`post`, `wait`, `close`, `responses`, `followups`, `list`). Also imported by the app as the shared file layer (locking, JSONL, ids, timestamps). Standard library only.
- `src/claudedesk/store.py`: data layer (incremental reads, read/archive/delete state, replies, follow-ups, project tabs). No GUI imports.
- `src/claudedesk/server.py`: local HTTP server (127.0.0.1, Host check, per-run token) for the UI.
- `src/claudedesk/app.py`: tray, window, notifications, taskbar badge, self-update loop. `update.py`: GitHub Releases updater. `winapi.py`: Win32 calls. `icon.py`: icon and badge drawing. `projects.py`: repo discovery from Claude Code session history.
- `src/claudedesk/assets/`: the UI (`index.html`, `app.css`, `app.js`, `markdown.js`). `assets/vendor/` is generated by `scripts/vendor.py`; don't edit it by hand.
- `skill/claude-desk/SKILL.md`: the skill users install into Claude Code. Keep it in sync with the CLI.
- `tests/`: pytest. `test_store.py`, `test_desk.py`, `test_followups.py`, `test_server.py`, `test_icon.py` are pure Python; `test_ui*.py` drive the real UI in Chromium via Playwright.

## Tests

```bash
pip install -r requirements.txt -r requirements-dev.txt
python -m playwright install chromium        # or set CHROMIUM_PATH to an installed Chromium/Edge
python -m pytest -q
```

On Windows, UI tests can use Edge directly: `CHROMIUM_PATH="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" python -m pytest -q`. Run the whole suite before you finish; UI timing tests should wait for state (`wait_for_function`, `wait_for_selector`), never sleep.

## Style

- The UI, code comments, docstrings and the skill are in Simplified Chinese. Keep new comments in Chinese and match the surrounding tone: short, explain *why*.
- Front end: plain ES5-style JavaScript (`var`, `function`, no arrow functions, no modules, no build step). Everything lives in the IIFE in `app.js`.
- CSS: all colors and sizes go through the custom properties on `:root` in `app.css`; themes, accents, density and reading width only change variables. Don't hard-code colors in rules or in JS.
- Python 3.10+, type hints where they help, no new runtime dependencies for `desk.py`.
- Never put real inbox content, personal paths or real project names into tests, docs or screenshots. Use placeholders such as `webapp`, `acme-data-pipeline`, `示例项目`. Regenerate the README screenshots with `python scripts/screenshots.py`.

## Commits

- Imperative subject line that says what changed for the user; optional body.
- No AI attribution trailers (`Co-Authored-By: Claude …`, `Claude-Session: …`, "Generated with Claude Code"). `.claude/settings.json` turns them off.
- Every green push to `main` is published as a release that installed copies update to. Only land tested changes on `main` and never force-push it.
